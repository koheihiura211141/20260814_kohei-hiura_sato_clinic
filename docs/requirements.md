# 佐藤医院 Webサイト 制作要件

この文書は、佐藤医院の「Webサイトリニューアル 制作依頼書」と「Webサイト 掲載原稿」を、Codex / ChatGPT が実装時に参照しやすい形へ整理した要件定義です。

## 1. プロジェクトの目的

- 患者が必要な情報へ素早くたどり着ける、分かりやすいナビゲーションにする。
- 今風で清潔感のあるデザインにより、安心感・信頼感を与える。
- 最終的にはスマートフォン・タブレットにも対応するレスポンシブデザインとする。
- 地域に根ざした医療機関として、親しみやすさと誠実さを感じられる見た目にする。

## 2. 今回の作業フェーズ

- 現在は **PC版（1440px基準）の既存デザインを維持したまま、ファイル構成とAI向け仕様書を整備する段階** とする。
- レスポンシブ対応は後工程で実施する。
- 今回は、既存ページを勝手にレスポンシブ化しない。
- ただし今後のレスポンシブ化を妨げる新しい固定配置や、不要な絶対座標依存は増やさない。

## 3. ページ構成の基本要件

制作依頼書上の最終構成は次の6ページ。

1. トップページ
2. お知らせ
3. 診療内容
4. 当院について
5. 診療時間・所在地
6. よくあるご質問

ご予約・お問い合わせについては専用ページ提案も可。

### 現在の実装について

現在のHTMLはトップページを中心とした単一ページ構成で、各セクションへアンカーリンクで移動する形式になっている。別ページ化は、ユーザーから明示的な指示があるまでは勝手に行わない。

## 4. トップページの基本構成

制作依頼書で定められた基本順序は以下。

1. ファーストビュー（ナビゲーション付）
2. 診療時間
3. お知らせ
4. 院長挨拶
5. 診療内容
6. 当院について
7. スタッフ紹介
8. アクセス（所在地）
9. フッター

### 表示ルール

- ファーストビュー、診療時間、お知らせはページ上部から順に配置する。
- アクセスはフッター直前に配置する。
- フッターは最後に配置する。
- お知らせはトップページに5件まで表示する。
- 診療内容はトップページに4件まで表示する。
- 「当院について」はトップページでは概要のみとする。

## 5. 機能要件

### MUST

- スマートフォン・タブレット対応（後工程で実施）
- お知らせを院側で投稿・更新できる構成を想定する
- Googleマップを「診療時間・所在地」ページとトップページに設置する想定
- 駐車場案内・公共交通機関の利用方法を掲載する

### WANT

- ご予約・お問い合わせ専用ページ

## 6. デザイン要件

- トーン：清潔感、親しみやすさ、地域に根ざした医療の印象
- 配色：白を基調に、淡いグリーンまたはブルーを差し色にする
- 写真：支給写真を活用し、視覚的に分かりやすくする
- 可読性：高齢者も読みやすい文字サイズ・行間・コントラストに配慮する
- ナビゲーション：見つけやすさを優先する
- キャッチコピー：「地域に根ざした医療」を目立たせる
- NG：必要以上に派手なビジュアルや装飾は避ける

## 7. 素材利用ルール

- ロゴは支給された `logo.png` を使用する。
- 写真・画像は支給素材を使用する。
- **支給画像以外の使用は原則禁止。**
- 新しい外部画像を使いたい場合は、実装前にユーザーへ確認する。
- アイコンは、サイト全体と調和する範囲で追加してよい。

## 8. 掲載原稿のルール

- 掲載原稿は確定テキストとして扱う。
- **原則として文章を要約・言い換え・省略・追記しない。**
- 文面の追加・変更が必要な場合は、実装前にユーザーへ確認する。
- 院名、住所、診療時間、連絡先などの基本情報は `specification.md` の「基本情報マスタ」を正とする。
- 既存サイトと基本情報マスタに差異がある場合、AIが独断で修正せず、差異を報告して指示を待つ。

## 9. GitHub Pages要件

- 公開対象の `index.html` はリポジトリのルート直下に置く。
- CSS、JavaScript、画像は `assets/` 配下に整理する。
- パスはGitHub Pagesで動作する相対パスを使用する。
- ビルドツールやフレームワークは、ユーザーの明示指示なしに導入しない。
- `meta name="robots" content="noindex, nofollow"` を維持する。
- フッターの学習用架空サイトの断り書きを維持する。

## 10. 変更時の原則

- 指定された箇所以外は変更しない。
- 既存デザインを無断で「改善」しない。
- 大規模なリファクタリングや命名変更を勝手に行わない。
- 1回の依頼では、必要最小限の差分で修正する。
- 修正後はローカルファイル参照切れ、アンカー、表示崩れを確認する。
